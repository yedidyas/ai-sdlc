# Autonomous Coding Agents

A landscape of the autonomous coding agents a platform team can run unattended as of October 2026: what each one is, how it orchestrates work internally, what it shipped recently, what it costs, what is actually known about its reliability, and what you still have to provide around it. The last part covers the models behind these agents (prices, benchmark standings, API drift). Companion note: [Coding Agent Orchestration and Sandboxes](coding-agent-orchestration-and-sandboxes.md).

## In one paragraph

As of October 2026 the coding agent itself is close to a commodity and the system around it is the product. The core loop fits in about 100 lines ([mini-swe-agent](https://github.com/SWE-agent/mini-swe-agent)), swapping harnesses with a self-hosted open-weight model held fixed moved resolve rates by only about 2 to 3 tasks out of 64 while token volume and wall time changed a lot ([imec aistack](https://aistack.imec-int.com/blog/harness-cost)), and OpenAI publishes its harness as open source ([Codex as a platform](https://developers.openai.com/blog/codex-as-a-platform)). What differs is the layer above the loop. Claude Code (late May 2026) and GitHub Copilot (October 1, 2026) both shipped "dynamic workflows", where a program rather than the model decides the next step ([A harness for every task](https://claude.dev/blog/a-harness-for-every-task-dynamic-workflows-in-claude-code/), [Copilot dynamic workflows](https://github.blog/changelog/2026-10-01-dynamic-workflows-in-copilot-cli-and-the-copilot-app/)). Every vendor now has an unattended, event-triggered mode, and Devin reports more asynchronously triggered sessions than interactive ones ([Cognition](https://cognition.com/blog/testing-development)). Nobody publishes a task success rate; the independent numbers are sobering: agent PRs in dotnet/runtime merged 67.9% of the time against 87.1% for Microsoft engineers ([Ten Months with Copilot Coding Agent](https://devblogs.microsoft.com/dotnet/ten-months-with-cca-in-dotnet-runtime/)), and merged agent PRs attract later fixes at 1.62 times the odds of merged human PRs ([arXiv 2609.26847](https://arxiv.org/abs/2609.26847)). Cost moves more with harness, effort setting and routing than with token price. What a platform team must supply is the same for every agent: a sandbox, an identity, CI that the agent cannot talk its way past, a budget cap, version pins and a durable place for state.

## How to read this note

- **Freshness.** Everything is "as of October 2026" (checked 2026-10-12). Versions carry release dates where the source gave one. "Recent" means April to October 2026.
- **Vendor claims.** Vendor-authored benchmarks and case studies are marked "(vendor)"; independent data (dotnet/runtime, the arXiv papers, Cockroach Labs, the Terminal-Bench leaderboard) is called out as such.
- **No reliability SLAs.** No vendor publishes a task success rate or reliability SLA for Claude Code, Codex cloud, Copilot cloud agent, Jules, Cursor or Devin; reliability numbers come from third parties or vendor case studies. This is a gap in the public record, not an oversight in this note.

## The shape of the landscape

Two layers get confused. The **harness** is the agent loop: tools, permissions, context management, the model call. The **orchestration** is what runs next, for how long, with what recovery. In 2026 the vendors sell both, but only the second is where unattended runs fail.

The table groups the agents by who decides the next step.

| Family | Members | Who decides the next step | Where state lives | Where it runs |
|---|---|---|---|---|
| Interactive and headless CLI harnesses | Claude Code, Codex CLI, Droid, Copilot CLI, Auggie, Kiro CLI, Amp | The model, turn by turn | Session files, repo, git | Your machine or CI runner |
| Cloud async agents | Devin, Copilot cloud agent, Codex cloud, Jules, Cursor cloud agents, Claude Code cloud sessions | The model, inside a task you assign | Vendor session store, branch, PR | Vendor VM or your self-hosted pool |
| Open-source platforms | OpenHands, mini-swe-agent, SWE-agent, OpenCode | The model; Agent Canvas adds triggers | Your infrastructure | Local, VM, your cloud |
| Code-defined workflows | Claude Code dynamic workflows, Copilot dynamic workflows, GitHub Agentic Workflows | The program ("The same steps run every time.") | Saved results per agent, safe outputs | In-session or Actions |
| Coordinator and factory layers | Cursor Projects, Kiro Crew, Devin managed Devins, Augment Cosmos, Factory automations | A coordinator agent or a rules engine | Vendor control plane | Vendor or hybrid |

The quote "The same steps run every time." is from [GitHub's launch note](https://github.blog/changelog/2026-10-01-dynamic-workflows-in-copilot-cli-and-the-copilot-app/), which contrasts dynamic workflows with `/fleet`, where the agent decides. [GitHub's concept doc](https://docs.github.com/en/copilot/concepts/agents/dynamic-workflows) lays it out in three rows: autopilot ("Copilot decides the next steps"), fleet (Copilot decides how to divide work) and dynamic workflow ("Carry out a process defined in code"). Anthropic's launch essay says the same about its own feature: subagents are "Claude, turn by turn", workflows are "The script" ([workflows docs](https://code.claude.com/docs/en/workflows)).

## Agent profiles

The first four profiles use six headings (what it is, how it orchestrates, recent releases from April to October 2026 unless noted, pricing, reliability and benchmark claims, what your platform team provides); the rest are condensed.

### Claude Code (Anthropic)

- **What it is.** Anthropic's terminal, IDE and cloud coding agent ([overview](https://code.claude.com/docs/en/overview)). The [Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview) is "A library that runs the Claude Code binary" (Python and TypeScript) and exposes tools, hooks, subagents, MCP, permissions, sessions and skills. Managed Agents is "A hosted agent harness that runs the agent loop" in an Anthropic-managed or self-hosted sandbox. Other languages can drive the same loop through "the CLI as a subprocess with the -p flag and --output-format json".
- **How it orchestrates.**
  - *Loop and checkpoints.* File-edit checkpoints and rewind exist, but "Checkpointing does not track files modified by Bash commands", edits made by subagents, or edits from other concurrent sessions; "Use git to revert them" ([Checkpointing](https://code.claude.com/docs/en/checkpointing)). "Checkpoint" here is not durable execution: nothing survives a lost pod.
  - *Dynamic workflows.* A JavaScript script spawns agents with `agent()`, `parallel()` and `pipeline()`. `Date.now()`, `Math.random()` and a no-argument `new Date()` throw, so a relaunched run repeats the same calls. On relaunch completed agents return saved results; "the first agent whose prompt differs runs again, and so does every agent after it" (A, B, C, D with B failing: A from cache, B, C, D run again). Limits: up to 16 concurrent agents by default (`CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS` 1 to 256 needs v2.1.269 or later), 4,096 items in one `parallel()` or `pipeline()` call, 1,000 agents per run; a stalled agent restarts at most five times; usage-limit hits pause the run (v2.1.271 and later) and a third hit fails the agent ([workflows docs](https://code.claude.com/docs/en/workflows)). The launch essay names the failure modes it targets: agentic laziness ("35 of the 50 items" then declares done), self-preferential bias and goal drift ([A harness for every task](https://claude.dev/blog/a-harness-for-every-task-dynamic-workflows-in-claude-code/)).
  - *Cloud sessions.* Each task gets a fresh VM with the repo cloned onto a new branch; three sessions were started "within 16 seconds of each other, each on its own machine" ([field guide](https://claude.dev/blog/claude-code-in-the-cloud/)). Per-PR auto-fix "subscribes to GitHub activity" and pushes a fix "if one is clear", with a blind spot: "GitHub does not emit a webhook when the base branch advances and creates a merge conflict". Handoff to the terminal is one-way (`--teleport`). GitHub credentials "stay encrypted on Anthropic's servers and never enter a session's VM" ([cloud sessions docs](https://code.claude.com/docs/en/claude-code-on-the-web)).
  - *Managed Agents.* An append-only session log sits outside a stateless harness and sandboxes are called as tools through `execute(name, input) -> string`; a crashed harness is rebooted from the log. Decoupling cut p50 time to first token by roughly 60% and p95 by over 90%; git tokens are wired into the remote at sandbox init so the agent never handles them ([Scaling Managed Agents](https://www.anthropic.com/engineering/managed-agents)). Beta header `managed-agents-2026-04-01`; "not currently eligible for Zero Data Retention or HIPAA Business Associate Agreement (BAA) coverage" ([overview](https://platform.claude.com/docs/en/managed-agents/overview)).
  - *Sandboxed Bash.* OS-enforced (Seatbelt on macOS, bubblewrap plus socat on Linux and WSL2; native Windows runs unsandboxed). Writes are limited to the working directory; network goes through a local proxy whose allowed domains start empty; but reads default to "Most of the machine, including credential files such as ~/.ssh and ~/.aws/credentials" unless you set `filesystem.denyRead` ([sandboxing docs](https://code.claude.com/docs/en/sandboxing)).
- **Recent releases.**
  - 2026-04-08: Managed Agents engineering post. 2026-04-16: Opus 4.7 with "API breaking changes versus Opus 4.6" ([release notes](https://platform.claude.com/docs/en/release-notes/overview)).
  - 2026-04-23: quality postmortem. Three harness changes, not model or API changes: default effort lowered from high to medium on Mar 4 (reverted Apr 7), a bug that cleared older thinking every turn from Mar 26 (fixed Apr 10 in v2.1.101), and a verbosity prompt line from Apr 16 (reverted Apr 20). "The API was not impacted"; Claude Code, the Agent SDK and Cowork were ([postmortem](https://www.anthropic.com/engineering/april-23-postmortem)).
  - Late May 2026: dynamic workflows (launch essay dated 2026-06-02 says "last week"). 2026-05-25: containment post and auto mode ([How we contain Claude](https://www.anthropic.com/engineering/how-we-contain-claude)).
  - October 2026: self-hosted environments in public beta on Team and Enterprise, off by default ([docs](https://code.claude.com/docs/en/self-hosted-environments)); routines in research preview with Scheduled, API (HTTP POST with bearer token) and GitHub triggers, on Pro, Max, Team and Enterprise ([docs](https://code.claude.com/docs/en/routines)).
  - Current: Claude Code 2.1.296 (2026-10-09; 2.1.289 shipped Oct 3), Claude Agent SDK for Python 0.2.165 (2026-10-08) ([model config](https://code.claude.com/docs/en/model-config)).
- **Pricing.** Plan-included (Pro, Max, Team, Enterprise) or API billing; the Agent SDK is free and the Action costs "GitHub Actions minutes plus API tokens" ([docs](https://code.claude.com/docs/en/github-actions)). Anthropic's breakdown: every turn resends the conversation; at Opus 5.5 list prices ($4 input, $20 output, $0.20 cache reads per million) 40 turns growing from 20K to 120K context send about 2.8M input tokens, about $1.62 with 90% cache reads; "A retry costs more than those savings" ([What a task costs on Opus 5.5](https://claude.dev/blog/what-a-task-costs-on-opus-5-5/)).
- **Reliability and benchmarks.** No published success rate. Anthropic's own harness study: a solo run took 20 minutes and $9, the full planner/generator/evaluator harness 6 hours and $200 ("over 20x more expensive"); tuning a separate skeptical evaluator "turns out to be far more tractable than making a generator critical of its own work" ([Harness design](https://www.anthropic.com/engineering/harness-design-long-running-apps)). Independent: Claude Code PRs waited longest for a first human review (median 12.6 hours) in a study of 37,623 PRs from December 2024 to July 2025 ([arXiv 2609.17598](https://arxiv.org/abs/2609.17598)). On Terminal-Bench 4.0, Opus 5.5 in Claude Code scored 64.85% at about $14.30 per trial ([leaderboard](https://www.tbench.ai/)). In DeepSWE's small pilot Claude Code scored 40% against 50% for the same model in mini-swe-agent ([DeepSWE](https://deepswe.datacurve.ai/blog/deepswe)).
- **What your platform team provides.**
  - *Budget.* `--max-budget-usd`, `--max-turns` (the Action's example uses `--max-turns 5`), workflow timeouts and GitHub concurrency controls ([headless](https://code.claude.com/docs/en/headless), [Actions docs](https://code.claude.com/docs/en/github-actions)).
  - *Version pins.* The April postmortem hit the Agent SDK too, and releases land several times a week, so pin the CLI or SDK version and the model ID. On Bedrock and Google Cloud's Agent Platform the `sonnet` alias resolves to Sonnet 4.5, on the Anthropic API to Sonnet 5.5; use full model names ([model config](https://code.claude.com/docs/en/model-config)).

### OpenAI Codex

- **What it is.** An open-source CLI (Apache-2.0, 0.162.1 on 2026-10-09), a desktop app, cloud tasks, an SDK and an app-server. OpenAI frames the harness as embeddable: `codex exec` for scripts and CI, the SDK to start, resume and stream tasks, app-server for products that stream events and handle approvals ([Codex as a platform](https://developers.openai.com/blog/codex-as-a-platform)).
- **How it orchestrates.**
  - *Loop.* Plan, edit, run tools, observe, repair, held together by durable project memory files. An OpenAI engineer ran GPT-5.3-Codex at Extra High reasoning for about 25 hours uninterrupted: about 13M tokens and about 30k lines of code, "an experiment, not a production rollout" ([Run long horizon tasks with Codex](https://developers.openai.com/blog/run-long-horizon-tasks-with-codex)). Goal mode "drive[s] toward a specific objective for hours or even days" ([changelog](https://learn.chatgpt.com/docs/changelog)).
  - *Subagents.* Enabled by default. Config keys: `agents.enabled`, `agents.max_concurrent_threads_per_session`, `agents.default_subagent_model`, `agents.default_subagent_reasoning_effort`. Guidance: "use parallel agents for read-heavy tasks such as exploration, tests, triage, and summarization. Be more careful with parallel write-heavy workflows"; subagent runs "consume more tokens than comparable single-agent runs" ([subagents docs](https://learn.chatgpt.com/docs/agent-configuration/subagents)).
  - *Headless.* By default `codex exec` runs in a read-only sandbox; `--sandbox workspace-write` allows edits; `danger-full-access` only in an isolated CI runner or container; `--ephemeral` avoids persisting session rollout files; `--ignore-user-config` and `--ignore-rules` for controlled automation; progress streams to stderr and only the final message goes to stdout ([codex exec docs](https://learn.chatgpt.com/docs/non-interactive-mode)).
  - *Cloud and Agents API.* Cloud tasks run in per-task workspaces from published environments with GitHub and, in beta, GitLab ([Codex cloud docs](https://learn.chatgpt.com/docs/cloud)). The Agents API (public beta 2026-09-10) exposes the Codex harness as a managed API: "OpenAI handles session orchestration, context compaction, and recovery" ([OpenAI changelog](https://developers.openai.com/api/docs/changelog)); sandboxes can be OpenAI-hosted, company-managed or from nine partners (Blaxel, Cloudflare, Daytona, DigitalOcean, E2B, Modal, Oracle, Runloop, Vercel) ([VKTR](https://www.vktr.com/ai-platforms/openai-launches-managed-agents-api-for-cloud-based-agents/)).
- **Recent releases.** 2026-05-21 goal mode leaves experimental; 2026-06-25 Codex Remote GA; 2026-08-19 GitLab support in Codex cloud (beta; self-managed webhooks need GitLab 19.0 or later); 2026-08-25 scheduled tasks triggered from Gmail, Slack and GitHub events; 2026-09-05 `codex mcp-server` removed (deprecated Aug 24) in favour of an app-server that "isn't supported for production workloads"; 2026-09-29 GPT-6.1 Sol in Codex; 2026-10-08 GPT-6.1 Sol Ultrafast ([changelog](https://learn.chatgpt.com/docs/changelog)). Earlier: the Codex app for macOS on 2026-02-02 and Windows on 2026-03-04, with worktrees and a detached HEAD by default. Ona (the cloud development environment company) agreed to join the Codex team, closing 2026-08-10 ([Ona](https://ona.com/stories/ona-joins-openai)).
- **Pricing.** Open-source CLI; ChatGPT plan or API billing; the Agents API has "no additional fees for the API itself" (you pay tokens and tools). Fast mode (formerly Priority) and Ultrafast: GPT-6 Astra Ultrafast is $60 input and $300 output per million, 6x Standard ([OpenAI pricing](https://developers.openai.com/api/docs/pricing)).
- **Reliability and benchmarks.** Codex PRs were reverted 6.1% of the time against 11.5% for human PRs (odds ratio 0.50) in the 37,623-PR study (data to July 2025) ([arXiv 2609.17598](https://arxiv.org/abs/2609.17598)). The Codex repos merged 7,688 PRs in 12 months, 16% of them bug fixes, about 1.32M lines, growing from about 124 merged PRs a month in mid-2025 to around 1,000 a month a year later ([OpenHands](https://www.openhands.dev/blog/coding-agents-and-technical-debt)). On Terminal-Bench 4.0, GPT-6 Astra and GPT-6.1 Sol in Codex both scored 58.18%, at about $9.90 and $1.92 per trial ([leaderboard](https://www.tbench.ai/)). On Real-SWE (private codebases) GPT-6 Astra in Codex CLI leads at 46.25% ([Real-SWE](https://withspecific.com/benchmarks/real-swe)). OpenAI says harness design raised GPT-5.6 Sol's ARC-AGI-3 score "from 13.3% to 38.3% while reducing output tokens sixfold" (vendor claim).
- **What your platform team provides.** Pick the sandbox explicitly per run (the default is read-only), keep `danger-full-access` for throwaway runners, pin the CLI, and expect churn (the MCP server was removed within two weeks of deprecation; do not build production paths on the app-server).

### GitHub Copilot cloud agent, CLI and Agent HQ

- **What it is.** The cloud agent (formerly the Copilot coding agent) "researches, plans, edits and opens PRs in an ephemeral cloud environment" and supports automations and an API ([docs](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/cloud-agent)). Copilot CLI adds dynamic workflows, `/fleet` and local and cloud sandboxing. Agent HQ (announced 2025-10-28) is "mission control, a single command center to assign, steer, and track the work of multiple agents"; agents from Anthropic, OpenAI, Google, Cognition and xAI "will become available directly within GitHub" under a Copilot subscription ([GitHub](https://github.blog/news-insights/company-news/welcome-home-agents/)). Current GitHub docs list Anthropic Claude and OpenAI Codex as supported third-party agents, and steering is not available for them. Agent HQ is about assigning and tracking agents, not durable execution.
- **How it orchestrates.**
  - *Environment.* "its own ephemeral development environment, powered by GitHub Actions", customized by a job that "MUST be called `copilot-setup-steps`" (`timeout-minutes` maximum 59). Larger, self-hosted (ARC) and Windows runners are options; ephemeral single-use runners are recommended; the integrated firewall "is not compatible with self-hosted runners" ([environment docs](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/customize-the-agent-environment)).
  - *Dynamic workflows (2026-10-01).* Programs that mix automated steps with agents: parallel stages, structured hand-offs, cross-verification, and checkpoints to "pause ... so you can review results and resume". Limits can stop a run, "but its status and saved results are kept so that you can resume it later"; a raised limit "is a total for the run, including usage before it stopped"; and agents "can give different answers on different runs" even with the same steps ([GitHub docs](https://docs.github.com/en/copilot/concepts/agents/dynamic-workflows)).
  - *Agentic Workflows (public preview).* Markdown with YAML frontmatter compiled to a hardened `.lock.yml` Actions workflow; agents run read-only in firewalled containers; writes happen only through declared safe outputs in separate jobs after threat detection; "Sensitive credentials are kept in isolated downstream jobs"; engines: Copilot (default), Claude, Codex, Gemini ([docs](https://docs.github.com/en/copilot/concepts/agents/about-github-agentic-workflows)).
- **Recent releases.** 2026-07-30 stacked PRs in public preview ([GitHub](https://github.blog/changelog/2026-07-30-stacked-pull-requests-are-now-in-public-preview/)); 2026-09-01 Copilot code review can approve PRs (off by default, public preview, approval dismissed when new commits land, configurable by file path) ([GitHub](https://github.blog/changelog/2026-09-01-copilot-code-review-can-now-approve-pull-requests/)); 2026-09-22 OpenTelemetry export of agent sessions via `managed-settings.json`, prompt and response content excluded by default ([GitHub](https://github.blog/changelog/2026-09-22-opentelemetry-in-the-github-copilot-app/)); 2026-10-01 dynamic workflows; 2026-10-07 local sandboxing GA on Microsoft eXecution Container (MXC), controlling internet, local network, Git credential and GitHub CLI credential access, with policies that apply "regardless of which model Copilot uses" ([GitHub](https://github.blog/changelog/2026-10-07-local-sandboxing-for-github-copilot-now-generally-available/)). Churn: GitHub Models was retired in summer 2026 ([Simon Willison](https://simonwillison.net/2026/Aug/9/github-models-is-now-retired/)); a secondary summary reports six models retired from every Copilot surface on 2026-09-01 with about a month's notice ([DEV](https://dev.to/leobaniak/github-copilot-retires-six-models-on-september-1-and-every-copilot-surface-is-in-scope-2ohc)).
- **Pricing.** Included in paid Copilot subscriptions; local sandboxing is "Included at no additional cost".
- **Reliability and benchmarks.** The best independent dataset on any vendor agent: dotnet/runtime, May 2025 to March 2026, 878 cloud-agent PRs, 535 merged, 253 closed, 90 open; success rate 67.9% (merged over merged plus closed) against 87.1% for Microsoft engineers (3,082 PRs) and 79.7% for community contributors. Reverts: 3 of 535 merged agent PRs (0.6%) against 33 of 4,251 non-agent PRs (0.8%). Across seven repositories: 2,963 PRs, 68.6% merged. The author warns the agent is assigned more bounded tasks and the data "should be taken directionally" ([Toub](https://devblogs.microsoft.com/dotnet/ten-months-with-cca-in-dotnet-runtime/)). Because admins can now let a Copilot approval count toward required reviews, an agent's PASS needs independent evidence behind it.

### Devin (Cognition)

- **What it is.** Cognition's autonomous cloud software engineer, with Devin Review, automations, computer-use testing and analytics ([release notes](https://docs.devin.ai/release-notes/overview)).
- **How it orchestrates.**
  - *Machines.* Cognition argues containers fail long-running agents because they cannot snapshot and restore full state across the async gaps of CI and review, so it built hypervisor-level microVM snapshots of "memory, process trees, and filesystem". The microVM work "took over a year of hypervisor engineering" and the orchestration layer "over three quarters of dedicated engineering", managing thousands of concurrent VMs; "A containerized agent can only survive async breaks by burning compute to stay alive" ([What We Learned Building Cloud Agents](https://cognition.com/blog/what-we-learned-building-cloud-agents)).
  - *Managers and children (2026-03-19).* Each managed Devin "is a full Devin, running in its own isolated virtual machine"; the coordinator scopes work, monitors progress, resolves conflicts and compiles results, can message children, "Monitor ACU consumption", and put children to sleep or terminate them; an example prompt says "10 at a time" ([Cognition](https://cognition.com/blog/devin-can-now-manage-devins)).
  - *Verification.* Test plans "must be grounded in source, not assumptions"; "Devin will lie less about its findings if it annotates its expected behavior right before performing an action"; repetitive steps such as login are extracted into deterministic scripts; engineers run 10 to 20 Devins in parallel, each with its own dev server ([Verifying Agentic Development at Scale](https://cognition.com/blog/testing-development)). Devin Review catches "an average of 2 bugs per PR, of which roughly 58% are severe", and works best "when the coding and review agents do not share any context beforehand"; its position on swarms narrowed to "writes stay single-threaded" ([Multi-Agents: What's Actually Working](https://cognition.com/blog/multi-agents-working)).
  - *Fusion (2026-06-29).* A frontier main agent that "should take minimal actions" and by default "delegate and monitor" a cheaper sidekick with mid-session routing. On FrontierCode 1.1 Extended (vendor): Fusion 63.1 at $1.35 per task against Fable 5 (xhigh) 64.9 at $10.53 ([Devin Fusion](https://cognition.com/blog/devin-fusion)).
- **Recent releases.** 2026-03-19 managed Devins; 2026-04-22 and 2026-04-23 the multi-agent and cloud-agent posts; 2026-05-29 computer-use testing post, with more Devin sessions triggered asynchronously than interactively; 2026-06-04 productivity estimator and guarantee; 2026-06-29 Fusion; 2026-10-07 release notes (merge-queue status "In merge queue", "Stack is approved" only when every open PR is approved, private keys in saved secrets redacted line by line, "ACUs per merged PR" counting PRs merged in the selected period).
- **Pricing.** Commercial, ACU-based. Cognition "will fund your usage up to $10M" if Devin delivers less engineering value than customers pay for; unmerged PRs and sessions classified unproductive count as not useful ([guarantee](https://cognition.com/blog/ai-guarantee)).
- **Reliability and benchmarks.** Cognition's estimator reaches r_log 0.74 and "appears to be unbiased" against engineers' own estimates (258 sessions, 126 users); the unproductive-session classifier removes about 1 to 20% of sessions depending on customer (vendor, [Cognition](https://cognition.com/blog/ai-productivity)). Independent: Devin PRs were reverted 14.5% of the time (odds ratio 1.31) in the 2024-2025 data ([arXiv 2609.17598](https://arxiv.org/abs/2609.17598)); that is an older Devin generation.
- **What your platform team provides.** Less than for the others, because Devin brings its own machines; you still own secrets hygiene (the product now redacts keys in logs), merge-queue and review policy, an outcome metric (cost per merged PR, not per session) and an exit plan, since the lock-in is heavy.

### OpenHands, mini-swe-agent and SWE-agent (the open-source line)

You provide runtime hosting, secret scoping, upgrade budget and a sandbox.

## What converged across vendors

1. **Writes are split from reasoning.** Agentic Workflows write only through safe outputs; `codex exec` and `droid exec` default to read-only; Kiro: "Enforced by the host, not requested politely in a prompt".
2. **Work becomes event-triggered.** Routines, Codex scheduled tasks (2026-08-25), Factory automations (GA 2026-09-30), Cursor Projects, OpenHands Agent Canvas, Kiro cloud sessions (2026-08-18). The silent-failure warning travels with it: "Don't mistake a failed read for a quiet day" (a down MCP server still lets the run start and the agent reports "nothing new"); a post counts as sent only if Slack returns `"ok": true` and a message `ts`, and an unclear result is marked "maybe posted" ([Anthropic](https://claude.dev/blog/building-effective-agent-automations/)).
3. **Verification becomes the product** (Augment's Verifier, Devin's grounded test plans, Kiro's mandatory diagnostics, Factory's executable standard of completion) and **routing moves into the harness** (Factory Router, Devin Fusion, Codex `agents.default_subagent_model`).
4. **Value is measured on outcomes** (cost per merged PR, Cognition's estimator) and **humans stop approving every step**: 93% of prompts approved, so Anthropic invests in containment and auto mode, and Augment's Risk Analyzer auto-approves low-risk PRs.

### Cost, caching, routing and drift

- **Cache discipline is the cost lever.** About 96% of tokens in the Opus 5.5 runs were cached input; Anthropic says cache reads "make up the majority of agentic and coding work costs" ([Opus 5.5 launch](https://www.anthropic.com/claude-opus-5-5)). Multipliers: reads 0.1x base input (0.05x on Opus 5.5 and Sonnet 5.5, 0.025x on Fable 5.1), 5-minute writes 1.25x, 1-hour writes 2x, batch 50% off, `inference_geo: "us"` 1.1x, and the Claude 4.7 and later tokenizer yields about 30% more tokens for the same text ([pricing](https://platform.claude.com/docs/en/about-claude/pricing)). Changing tool definitions or `output_config.effort` invalidates cached blocks ([prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)). OpenAI: one write plus nine reads cost 2.15x against 10x uncached ([OpenAI](https://developers.openai.com/api/docs/guides/prompt-caching)). A self-reported case: about 6.47B uncached input tokens produced a $37,901.73 Bedrock bill when caching silently failed ([HN](https://hn.algolia.com/api/v1/items/47933355)).
- **Cost per merged feature, not per token.** $3 to $33 for the same feature, harness alone about 2.5x, and a deterministic test oracle that "caught the review gate happily merging code that passed as few as 12 of 38" unit tests ([Insight APAC](https://blog.apac.insight.com/2026/07/06/cost-to-a-merged-feature)). In one four-model Claude Code rig tasks resolved 91% when the optional verifier was called and 43% when skipped; 3 to 5 hand-offs resolved 90% at $2.41 per trial, 6 or more resolved 50% at $9.51; delegated security subtasks were refused (0 of 14 solved) while the same model solved 6 of 6 when asked directly (one run, pre-5.5 models) ([Quesma](https://quesma.com/blog/multi-model-claude-code-refusal-terminal-bench/)).
- **Routing.** Keep a cost-routing pool at two models that differ on speed, quality or cost ([Try-Works](https://try.works/first-principles-of-model-routing)); the 2025 mini-SWE-agent roulette found random per-step switching between near-peers beat either alone (39 against 33 and 32 on 50 instances) ([SWE-bench](https://www.swebench.com/post-250820-mini-roulette.html)); a router claiming Astra-level Terminal-Bench 4.0 at 52% of cost is vendor-reported ([Show HN](https://hn.algolia.com/api/v1/items/49911500)). DeepSeek V4.1-Flash carried about 31.2% of tokens in OpenRouter's 19-model weekly view ([OpenRouter](https://openrouter.ai/rankings)).
- **Sampling knobs are gone.** Non-default `temperature`, `top_p` and `top_k` return 400 on Claude 4.7 and later ([deprecations](https://platform.claude.com/docs/en/about-claude/model-deprecations)); GPT-6 Astra rejects custom temperature, top_p and logprobs; Gemini deprecated them on 2026-07-21. Determinism has to live in the controller.
- **Request code breaks per model.** Opus 5.5 rejects disabled thinking, manual `budget_tokens`, forced `tool_choice` and assistant prefill with HTTP 400, and thinking blocks can come first so `content[0].text` breaks ([migration guide](https://platform.claude.com/docs/en/models/opus-5-5/migration-guide)); "Code written for Claude Haiku 4.5 can break on Claude Haiku 5.5" ([release notes](https://platform.claude.com/docs/en/release-notes/overview)).
- **The model behind the string changes.** Gemini routes `gemini-3.7-flash` to 3.8; classifier refusals return `stop_reason: "refusal"` as a normal response and can fall back to another model (Opus 5.5 to Opus 4.8 for most cyber tasks) ([refusals](https://platform.claude.com/docs/en/build-with-claude/refusals-and-fallback)); fallbacks lose thinking blocks and cross-provider fallback makes the target "reason fresh" ([LiteLLM](https://docs.litellm.ai/docs/proxy/reliability)). Record the served model per call.
- **Calendar.** Sonnet 4.5 retires on Anthropic's API 2026-11-30 (replacement `claude-sonnet-5-5`), while on Google Cloud its page says "Not sooner than Sept 29, 2026" with no firm date ([Sonnet 4.5 on Google Cloud](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/partner-models/claude/sonnet-4-5)); Haiku 4.5 (not sooner than 2026-10-15) and Opus 4.5 (not sooner than 2026-11-24) carry the same floors on both platforms; OpenAI's Evals platform goes read-only 2026-10-31 and shuts down 2026-11-30 ([OpenAI deprecations](https://developers.openai.com/api/docs/deprecations)); Claude 3 Haiku retired on Anthropic's API 2026-04-20 but Google Cloud scheduled 2026-08-23 ([Google Cloud](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/deprecations/partner-models)).
- **Provider incidents are routine.** The 50 most recent incidents on Anthropic's status feed, 2026-07-27 to 2026-10-07 as of 2026-10-12 (the endpoint caps at 50, so the window slides), 35 mentioning models, API or Platform, including a critical "Elevated errors across all models" on 07-29 ([status](https://status.claude.com/api/v2/incidents.json)). OpenAI now separates 429 `slow_down` from 503 `server_is_overloaded`. A daily benchmark found effort "low" cut output tokens 62% and accuracy 8.3 points, and could not tell Opus 5 from Opus 5.5 at 99%: watch token counts and served model ID, not pass rates ([livenerf](https://github.com/ninjahawk/livenerf)).
- **Which model for which phase (derived from the verdicts above).** Opus 5.5 for planning, critics and the hardest phase; Sonnet 5.5 at low or medium effort for editors (at max effort it scored lower on FrontierCode because it ran the code-review skill across many subagents, per its [launch post](https://www.anthropic.com/claude-sonnet-5-5)); Haiku 5.5 only for narrow work such as summaries and compaction; DeepSeek V4.1-Flash or GPT-6.1 Sol as the cheap side of a two-model router; skip Fable 5.1 for most SDLC phases.
